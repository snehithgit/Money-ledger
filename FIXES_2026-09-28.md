# Finance Tracker integrity fixes — 2026-09-28

Implemented after the code/core-logic audit.

## Data integrity
- Manual classifications are now protected from bulk rule re-application.
- Rule-created labels, commitment payments and goal contributions carry rule provenance and are removed/replaced safely on rule re-evaluation.
- Existing pre-provenance databases are backfilled so already-reviewed transactions are treated as manual and old rule matches remain identifiable.
- Deleting a rule preserves the transaction while removing rule-owned derived links and invalid foreign-key references.
- Commitment status reads are pure: `auto_confirm` no longer inserts payment rows on GET.
- Transaction-to-commitment allocations cannot exceed the transaction amount.
- `allow_multiple_transactions=False` is enforced for a commitment period.
- Manual commitment contributions are rejected when the commitment does not allow them.
- Quick Add transfers now create linked debit/credit transaction pairs so total assets are unchanged.
- Deleting one side of an internal transfer deletes the linked pair atomically.
- Category spending uses transaction splits when they exist.
- Split totals are validated before the parent transaction is patched in the UI.
- SQLite foreign keys are enabled.

## Recurrence/reporting
- Commitment history now includes missing months instead of only months that already contain payments.
- Late status uses due-day/current-period information.
- Monthly, quarterly, yearly and weekly recurrence are interpreted by the status engine; unsupported custom schedules surface `needs_review` instead of being silently guessed.
- Goal results include current-year YTD contribution and annual scheduled target fields.
- Added the missing `/api/reports/trend` endpoint.
- Dashboard calendar-date construction no longer passes local dates through UTC ISO conversion.
- INR formatting preserves paise.

## Imports and validation
- Uploaded archive names are reduced to a safe basename before writing to the archive directory.
- Invalid import account IDs return a client error rather than producing an attribute error.
- A reused PhonePe transaction ID with conflicting facts is treated as an import conflict, not as a second transaction.
- Rule fields/operators/actions are validated; empty `contains`, invalid `range`, empty rule conditions/actions and nonexistent rule action targets are rejected.
- Positive-amount/range validation was tightened on financial request schemas.

## Upgrade/seed behavior
- Added Alembic migration `0002_integrity_provenance.py`.
- Startup contains a non-destructive additive compatibility bridge for older databases originally created only with `create_all()`.
- Seeded categories/accounts/rules/goals/commitments/labels now retain stable IDs through the Setting table, so renaming a seeded item does not recreate it on restart.
- Frontend direct dependency versions are pinned rather than semver ranges.

## Regression tests added
`backend/tests/test_integrity_regressions.py` covers:
- manual classifications surviving Apply All Rules;
- read-only auto-confirm status;
- allocation caps;
- balanced linked transfers;
- split-aware category reports;
- rename-safe seeded commitments;
- trend endpoint availability.

## Later enhancement: commitment payment calendar

- Added `paid_date` to `CommitmentPayment` so each commitment contribution carries the actual payment date.
- Added `/api/commitments/calendar?month=YYYY-MM` for a month-view calendar payload.
- Commitments page now shows a monthly calendar grid with highlighted paid dates and day details.
- Manual commitment entries can now record the paid date explicitly.
